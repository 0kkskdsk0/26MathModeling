# 用 Notebook 做叙事性数据分析

## 核心定位

Notebook 就是分析工具本身。不要先用单独的 .py 脚本把数据跑明白、再把结论誊进 notebook——那是把 notebook 当成展示结果的幻灯片。正确做法是像人类数据分析师一样，在 notebook 里一步一步推进：提出一个问题，写代码回答它，看着真实输出写解读，再由这个解读引出下一个问题。分析的思考过程发生在 notebook 里，而不是发生在 notebook 之外。

产出的 notebook 首先是一篇**叙事文档**，其次才是代码。它的读者是需要理解分析结论的人，不一定读代码。

## 编辑与执行机制

- 对 `.ipynb` 的一切结构化读写，遵循项目中的 `edit-notebook-with-nbformat` skill，禁止直接对 JSON 做字符串替换。
- 执行 cell 用 `jupyter nbconvert --to notebook --execute --inplace <file>` 或等价的 nbclient 调用，让输出真实保存在 notebook 里。
- 工作节奏是增量式的：写一组"前三件套"（见下），执行，拿到真实输出后再写结果解读，然后规划下一步。不要一次性写完整篇再执行。

## 叙事结构规范

整篇 notebook 按以下骨架组织：

### 1. 开篇

- 可选的一行说明 cell：本文件的用途，一句话即可。
- 标题 cell（`# 标题`）：讲清楚四个东西——研究的问题是什么，为什么这个问题值得分析（它支撑哪个后续决策），当前要检验的候选做法或假设是什么，以及可复用逻辑存放在哪个 utils 路径下。开篇要让读者不看任何代码就能理解整篇分析的动机。

### 2. 分析单元（三件套）

每一个 code cell 都必须被 markdown cell 前后夹住，三者构成一个完整的分析单元：

**前置 markdown**（`## 分析N：主题` 或同级别的节标题）回答"为什么做这一步"：
- 这一步研究的主题和目的。
- 背后的推理：为什么这个统计量或这张图能回答当前的问题。例如"同一孕妇同一孕周的真实值是确定的，重复检测的差异就纯粹来自测量误差"——先讲清推理，读者才知道代码在算什么。

**code cell** 保持薄：
- 数据加载、指标计算等会复用或实现细节较重的逻辑，一律从 utils 导入（见"代码分层"），cell 里只做编排。
- 用 print 输出关键统计量，数字是后文解读的素材。
- 图要少而精，一张图只服务当前这一步的论点。

**后置 markdown** 回答"结果说明了什么"：
- 引用执行结果中的**具体数字**做解读，禁止"如图所示效果很好"这类空泛表述。
- 给出这一步的结论，并明确回扣开篇提出的研究问题：这个结果对候选做法或假设意味着什么。
- 自然引出下一步要分析的问题，让各分析单元之间形成递进而非并列的流水账。

### 3. 小结（`## 小结`）

- 把各分析单元的证据汇总，指出它们共同支持的总结论。
- 说明这个结论对后续工作的约束或决策含义，例如它排除了哪种建模方法、支持哪种方法、为哪个后续分析提供了量化基础。分析不能停在"发现了现象"，必须落到"所以接下来该怎么做"。

## 代码分层

Notebook 只保留分析叙事和编排代码。凡是符合以下任一条件的代码，都必须下沉到 utils：

- 会被多个 cell 或多个 notebook 复用。
- 实现细节会分散读者对叙事的注意力，例如编码处理、列名映射、字符串解析。

存放路径按 `utils/<任务类别>/<问题编号>/<模块名>.py` 组织，例如 `utils/DataExplore/problem2/nipt_data.py`。任务类别描述这次分析属于哪类工作，问题编号对应当前分析的具体题目或子任务，使得不同问题的分析互不污染。

utils 模块的写法要求：
- 模块 docstring 说明它服务哪个问题的哪类分析。
- 常量和魔法数字提到模块顶部并命名，例如阈值 `Y_THRESHOLD = 0.04`。
- 每个函数写 docstring，说明产出什么、用于量化什么。
- 函数保持纯粹：输入 DataFrame 或路径，返回数据，不做绘图和打印，把展示留给 notebook。

## 完成前检查清单

- [ ] 每个 code cell 上方都有解释目的与推理的 markdown cell。
- [ ] 每个 code cell 下方都有引用具体输出数字的解读 markdown cell。
- [ ] 所有 cell 已按顺序执行，输出保存在 notebook 中，无报错。
- [ ] 读者跳过所有 code cell 只读 markdown，也能完整跟上分析的逻辑和结论。
- [ ] 复用逻辑已全部移入 `utils/<任务类别>/<问题编号>/`，notebook 中没有大段实现细节。
- [ ] 结尾有小结，明确给出对后续工作的决策含义。
