# 写作审稿规则

只有用户明确要求写作层面的审稿、润色、“修改意见”“优秀论文写法”“加分项”或提分建议时，才使用本参考。

普通 Markdown 转 LaTeX、格式排版或编译修复时，不要加载或应用本参考。默认场景中必须保留用户原文；必要时只报告“内容层面未审查”。

不要用本参考覆盖队伍已经确定的事实模型、代码输出或数值结果。

## 审稿输出形式

简短审稿时使用：

```text
必须改：
1. [位置] 问题 -> 原因 -> 修改方向

加分优化：
1. [位置] 建议 -> 可插入写法
```

完整审稿时按章节组织：摘要、问题重述、问题分析、模型假设、符号说明、建模与求解、结果、验证、模型评价、参考文献、附录、LaTeX。

## 全文叙事

高质量数模论文通常不是几个小报告拼在一起。检查以下方面：

- 各小问的输出是否自然支撑后续小问；如果没有递进关系，论文是否解释原因。
- 摘要、问题分析、模型章节和最终结果是否讲的是同一条主线。
- 每个模型是否有明确角色：基准、扩展、验证、比较、优化或决策支持。
- 论文是否区分“为什么选这个方法”和“程序怎么实现”。
- 最强贡献是否在前文可见，而不是埋在附录或某张表格里。

常见修改方向：

- 在后续小问前增加承接句。
- 给每个模型加一句角色说明。
- 把代码过程叙述移到附录或说明中。
- 摘要中结果出现顺序与题目小问顺序保持一致。

## 摘要

摘要应最后写，且信息密度要高。应包含：

- 问题目标。
- 核心模型或方法。
- 关键算法或求解策略。
- 主要数值结果或排序。
- 验证、误差或敏感性证据。
- 最终决策或解释。

避免：

- “效果较好”“具有一定参考价值”“模型合理”等空泛判断。
- 每个小问都使用同一种句式。
- 描述文件处理、软件或代码行为。
- 只给方法不给结果。

可借鉴的结构：

```tex
针对问题一，本文先将【对象】转化为【数学任务】，在【约束/数据特征】下建立【模型名称】，
并采用【算法】求解，得到【关键结果】；进一步通过【检验方式】说明【结论】。
```

该结构只能作为骨架。所有占位符都必须替换为有来源的内容。

## 问题重述

好的问题重述应压缩背景，并把每个小问转化为数学任务。

检查是否说明：

- 研究对象。
- 已知条件。
- 未知目标。
- 约束条件。
- 需要输出的结果。
- 各小问之间的关系。

避免大段照抄题面。避免“进行分析并给出建议”这类空话，除非后面立刻转成可量化任务。

## 问题分析

问题分析应在公式出现前解释为什么选择这个模型。

对每个小问检查：

- 问题真正困难的地方是什么。
- 有哪些数据或物理机制可用。
- 所选模型为什么适合这个结构。
- 将产出什么结果。
- 会采用什么验证或比较方式。

较弱写法：

```text
为了解决问题一，我们建立回归模型并进行求解。
```

较好写法：

```text
问题一的目标变量随【变量】呈现【趋势】，且观测样本具有【特征】，因此可先用【方法】刻画
主要影响关系，再用【指标】检验预测误差。
```

## 模型假设

模型假设应是真实的建模选择，而不是照搬题目条件。

较好的假设通常会：

- 限定简化范围。
- 说明输入或参数处理约定。
- 有理由地忽略次要因素。
- 确定时间、空间或数据聚合尺度。

较弱的假设包括：

- 题目已给数据时仍写“所有数据真实可靠”。
- 不限定范围地写“忽略一切外界因素”。
- 把题目规则改写成假设。
- 结尾套用“后续会验证合理性”的空话。

## 符号说明

检查：

- 只列重要符号，不把临时变量全部堆进去。
- 同一个符号不要有两个含义。
- 有单位的量应给出单位。
- 向量、矩阵、标量的约定要清楚。
- 符号表应和后文公式一致。

## 模型建立

重要公式需要“写作夹心”：

1. 先说明为什么需要这个关系。
2. 再给出公式。
3. 最后解释每个关键项的含义，以及该公式后续如何使用。

优化问题应说明：

- 决策变量。
- 目标函数。
- 约束条件。
- 可行域。
- 求解方法，以及终止条件或参数选择。

统计或数据模型应说明：

- 预处理做了什么。
- 如果使用训练/验证划分，要说明划分方式。
- 指标定义。
- 误差或稳健性证据。

物理模型应说明：

- 从机理或守恒关系出发。
- 明确近似条件。
- 推导保持可读。
- 长推导放入附录。

## 结果、图片和表格

每张图表都应该为某个论断提供证据。

检查：

- 图表是否出现在被引入后或讨论附近。
- 图题/表题是否具体到足以理解内容。
- 正文是否解释趋势、对比或含义。
- 关键数字是否写进正文，而不是只放在表里。
- 表格数值精度和单位是否一致。
- 比较表中的最优值只在合适时加粗。

差写法：

```text
结果如图所示。
```

较好写法：

```text
由图~\cref{fig:cost-compare} 可见，方案二在【指标】上低于基准方案【数值】，
说明【机制性解释】。
```

## 验证与敏感性分析

论文如果能说明结果为什么可信，会明显更稳。根据模型类型检查：

- 误差分析。
- 残差分析。
- 交叉验证。
- 敏感性分析。
- 极端情形测试。
- 多模型对比。
- 与已知结论或领域约束对照。

不要机械要求每一种验证方法。推荐与模型最匹配的一种或几种。

## 模型评价与推广

模型评价要具体。

较好的缺点写法：

- 说明模型在哪个具体条件下可能失效。
- 提到数据量、参数、噪声、时间尺度或假设限制。
- 给出合理的改进路径。

避免：

- “模型具有较强普适性”。
- “仍有不足，有待进一步研究”。
- 把模型正常属性包装成优点。

## 附录

附录内容应能被正文追踪：

- 每个附录项目都在正文中被提到。
- 代码对应正文实际使用的方法。
- 长推导与正文公式一致。
- 大表格与正文结果来源一致。
- 不出现无关调试输出、个人路径或身份信息。
